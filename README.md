# AI 피트니스 & 식단 플래너

설문 한 번으로 일주일 운동과 식단을 만들고, 기록을 읽어 다음 주를 다시 짜는 웹 서비스.

추천을 AI에 통째로 맡기지 않았습니다. 트레이너가 하던 판단 — 아픈 곳을 피하고,
운동 강도에 맞춰 먹을 것을 정하고, 못 한 날을 다시 배치하는 것 — 을 규칙으로 옮기고,
AI는 규칙이 못 하는 자리(사진 읽기, 자유 질문)에만 씁니다.

## 실행

터미널 두 개가 필요합니다. **백엔드를 먼저** 켜세요.

```bash
cd fitness-backend-js && npm start
```

```bash
cd fitness-app && npm run dev -- --port 5174
```

접속: **http://localhost:5174**

| | 주소 |
|---|---|
| 프론트엔드 | http://localhost:5174 |
| 백엔드 (JS) | http://127.0.0.1:8003 |
| 백엔드 (파이썬, 비교용) | http://127.0.0.1:8002 |

프론트엔드가 어느 백엔드를 볼지는 `fitness-app/.env`의 `VITE_API_BASE_URL`이 정합니다.

## 처음 설치할 때

```bash
cd fitness-app && npm install
cd ../fitness-backend-js && npm install
```

파이썬 백엔드(비교용)까지 쓰려면:


## 구조

```
fitness-app/            React 19 + Vite — 화면
fitness-backend-js/     Express + Drizzle — 지금 쓰는 백엔드
fitness-backend/        FastAPI + SQLAlchemy — 같은 서비스의 파이썬 판(비교용)
fitness-backend/data/   SQLite 파일 (두 백엔드가 같은 파일을 본다)
발표자료.pptx / .html    10분 발표용 슬라이드 17장
```

백엔드는 세 층으로 나눠 두었습니다.

| 층 | 하는 일 |
|---|---|
| `src/routes/` | 요청 검사(zod), 도메인 호출, 응답. 판단은 하지 않는다. |
| `src/domain/` | 서비스의 판단이 전부 여기. 데이터베이스도 프레임워크도 모른다. |
| `src/persistence/` | Drizzle로 읽고 쓴다. |

도메인이 순수 함수라 웹을 띄우지 않고 함수 하나로 시험할 수 있고,
그래서 백엔드 언어를 통째로 바꿀 수 있었습니다.

## 기능

**계획** — 설문(목표·경험·빈도·분할·시간·부상·보유 기구와 키·체중)을 받아 안전 관문을
통과시킨 뒤 요일별 운동과 식단을 만듭니다. 주 단위로 앞뒤 이동이 됩니다.

설문에서 키·체중을 넣으면 BMI가 눈금과 함께 바로 보이고(BMI 칸에 직접 넣으면 체중이
역산됩니다), **인바디·체중계 결과지 사진**을 올리면 거기 적힌 키·체중·체지방률·골격근량을
읽어 채워 줍니다. 그 값이 루틴 기준으로 쓰입니다 — 분할 자동 추천 상한, 세션당 동작 수,
유산소 배치, 고강도 세션 완화.

**체지방률·골격근량은 선택 입력**입니다. 비워 두면 지금까지처럼 키·체중(BMI)만으로
판단하고, 넣으면 BMI만으로는 갈리지 않는 체형까지 나눠서 추천합니다.

| 체형 | 판단 | 루틴 |
|---|---|---|
| 근육형 | BMI 높지만 체지방 낮음 / 골격근량 많음 | BMI 보정 없음, 분할 상한 5 |
| 마른비만형 | BMI 25 미만인데 체지방 높음 | 유산소 안 당김, 근력 우선 |
| 비만형 | BMI 25 이상 + 체지방 높음 | 유산소 앞으로, 동작 수 −1 |
| 근육 부족형 | 골격근량 지수가 근감소 기준 미만 | 고충격 제외, 강도 완화, 전신 위주 |
| 근감소 비만형 | 지방 많고 골격근량 적음 | 근력 우선 + 강도·충격 완화 |

같은 178cm·82.4kg이라도 체지방 12%면 근육형으로 5분할, 30%면 비만형으로 3분할이
나갑니다. 분할은 무분할(전신)부터 5분할까지 직접 고르거나
자동 추천에 맡길 수 있고, 고른 운동 일수보다 큰 분할은 선택지에서 빠집니다.

계획표의 운동 이름을 누르면 그 동작의 설명·영상으로 바로 넘어갑니다. 그날 기구가
없으면 운동 옆 **대체 운동**을 눌러 대신할 동작을 고르면 됩니다 — 지정된 대체 동작,
맨몸(집에서 가능), 가지고 있는 기구 순으로 보여주고, 고른 동작은 그 자리만 바뀌어
저장됩니다. 아픈 부위와 안전 제한은 대체 동작에도 그대로 적용됩니다.

운동은 종류에 따라 재는 단위가 다릅니다. 기구를 쓰면 **무게·세트·횟수**(`15kg · 4×10`),
맨몸이면 **세트·횟수**만(`4×10`), 걷기·실내 자전거·로잉처럼 이동하는 유산소는
**거리**(`1.8km(20분)`)로 처방하고, 기록 화면의 입력 칸도 같은 기준으로 바뀝니다.

**기록** — 달력에서 날짜를 골라 운동과 식단을 남깁니다. 칸 안에 계획·운동 부위·
섭취/소모 열량이 함께 보입니다. 식단은 문장으로 적거나 사진으로 올릴 수 있습니다.

소모 열량은 동작마다 다르게 잡습니다. 동작별 MET(스쿼트 6.0, 푸시업 8.0,
레터럴 레이즈 3.0, 실내 자전거 7.0 …)에 체중과 시간을 곱해 계산하고, 세트 운동은
세트 수로, 거리 유산소는 거리와 평균 속도로 시간을 되짚습니다. 기록 화면에서
운동마다 예상 소모가 바로 보이고, 소요 시간을 직접 적으면 그 시간이 우선합니다.

**리포트** — 수행률, 운동별 최고 기록, 계획 대비 영양 달성률. 다음 주 루틴을
자동으로 다시 만듭니다.

**성장** — 포인트와 뱃지. 기록에서 매번 다시 계산해 중복 지급되지 않습니다.

**음악** — **장르**(EDM·힙합·록·K-POP·팝·러닝·로파이·피아노 8종)와 **길이**(1곡·30분·1시간·2시간)를
고릅니다. 30분·1시간·2시간을 고르면 **그 길이짜리 플레이리스트 영상**을 찾는 줄이 6개 나옵니다
(논스톱 연속듣기, 헬스장 브금, 영문 채널 믹스, 러닝용, 광고 없는 롱플레이, 라이브 스트림) —
줄마다 검색 각도가 달라 서로 다른 영상이 열립니다. 1곡을 고르면 그 장르의 후보 곡 8개를
AI가 뽑아 주고, 그중 하나만 골라 틀 수 있습니다. 그날 세션 강도에 맞는 장르가 앞으로 나와
`추천` 표시가 붙고, 길이 기본값은 설문의 하루 운동 시간을 따릅니다. 즐겨 듣는 목록 주소는
저장해 두면 여기서 바로 열립니다.

특정 영상 ID를 박아 두지 않습니다. 영상은 내려가고 채널은 바뀌므로, 검색으로 열어 늘 살아
있는 결과를 보여줍니다. 실제 영상 제목·길이·썸네일까지 목록에 넣으려면 YouTube Data API 키가
따로 필요합니다.

**운동 찾아보기** — 문장으로 물어도 됩니다("집에서 할 수 있는 등 운동",
"무릎 아픈데 하체"). 동작 설명과 참고 영상을 함께 보여줍니다.

## AI 설정 (선택)

AI가 쓰이는 자리는 넷입니다 — 식단 사진, 체성분 결과지 사진, 문장 운동 검색, 음악 플레이리스트.
자격 증명이 있을 때만 켜집니다.
없으면 "직접 적어주세요"라고 안내하고 나머지 기능은 그대로 돌아갑니다.

`fitness-backend-js/.env`에 키를 넣으세요 (`.env.example` 참고).
파이썬 백엔드도 같은 파일을 읽습니다(`fitness-backend/.env`가 있으면 그쪽이 우선).

```
GEMINI_API_KEY=AIza...
```

Gemini와 Claude 중 자격 증명이 있는 쪽을 자동으로 씁니다.
자세한 내용은 [fitness-backend-js/README.md](fitness-backend-js/README.md).

## 두 백엔드가 같은 답을 하는지 확인하기

파이썬 백엔드를 8002에 띄운 뒤:

```bash
cd fitness-backend-js && npm run compare
```

24개 시나리오를 양쪽에 던져 JSON을 통째로 비교합니다. 현재 **24 / 24 일치**.

언어가 다르면 숫자도 달라집니다. 파이썬 `round(2.5)`는 2, JS `Math.round(2.5)`는 3이라
열량 계산이 1씩 어긋났습니다. `src/core/num.js`의 `pyRound()`가 파이썬 규칙을 따릅니다.
